# Using ralph with Claude Code

Claude Code is Anthropic's official CLI for Claude. It's ralph's primary adapter with first-class support.

## Setup

<Steps>

1. **Install Claude Code**

   ```bash
   npm install -g @anthropic-ai/claude-code
   ```

2. **Set your API key**

   ```bash
   export ANTHROPIC_API_KEY="sk-ant-..."
   ```

3. **Verify installation**

   ```bash
   claude --version
   ```

</Steps>

## Configuration

Set Claude as your adapter in `.ralph/config.toml`:

```toml
adapter = "claude"
```

That's all the ralph-specific config needed. Claude Code handles model selection and other options through its own configuration.

## Prompt Patterns

### Pattern 1: Task with Progress Tracking

```markdown
# Task: Add Unit Tests

Add comprehensive unit tests for all modules in `src/services/`.

## Context
- TypeScript project using Jest
- Follow existing test patterns in `src/__tests__/`
- Each service should have its own test file

## Requirements
- At least 80% code coverage
- Test both success and error paths
- Mock external API calls

## Progress Tracking
1. Check progress.txt for completed work
2. Update progress.txt after each service is tested
3. Run `npm test` to verify

## Completion
When all tests pass with >80% coverage, output:
<promise>COMPLETE</promise>
```

### Pattern 2: Refactoring with Verification

```markdown
# Task: Migrate to New API

Migrate all usages of `oldApi` to `newApi`.

## How to Find Work
```bash
grep -r "oldApi" src/
```

## Migration Rules
- `oldApi.fetch()` → `newApi.get()`
- `oldApi.send()` → `newApi.post()`
- Error handling stays the same

## Verification
Run `npm run typecheck` after each file change.

## Completion
When `grep -r "oldApi" src/` returns no results, output:
<promise>COMPLETE</promise>
```

### Pattern 3: Bug Hunting

```markdown
# Task: Fix Failing Tests

Fix all failing tests in the test suite.

## Current Status
Run `npm test` to see failing tests.

## Guidelines
- Read the test to understand intent
- Check the implementation
- Fix the bug (prefer fixing implementation over tests)
- If test is wrong, explain why in commit message

## Process
1. Run tests to see failures
2. Fix one failing test at a time
3. Commit after each fix
4. Repeat until all pass

## Completion
When `npm test` exits with code 0, output:
<promise>COMPLETE</promise>
```

## Performance Tips

### 1. Keep Prompts Focused

Large prompts consume tokens every iteration. Keep them concise:

```markdown
# Good: Focused prompt
Add tests for untested functions. Check progress.txt for status.

# Bad: Overly detailed prompt
[500 lines of instructions repeated every iteration]
```

### 2. Use File References

Instead of embedding content in prompts:

```markdown
# Good
See CODE_STANDARDS.md for coding guidelines.

# Bad
[entire coding standards document embedded in prompt]
```

### 3. Model Selection

Claude Code defaults to Sonnet, which works well for most tasks. For complex reasoning, you can configure Claude Code to use Opus, but this is handled through Claude Code's own settings, not ralph.

## Troubleshooting

### "Context too long"

Your codebase is too large for a single read. Strategies:

1. Focus the prompt on specific directories
2. Use `.claudeignore` to exclude files
3. Let the model navigate incrementally

### "Model keeps repeating"

The model isn't seeing state changes. Ensure:

1. Your prompt references state files
2. State files are being updated
3. Git changes are being committed

### "Unexpected exits"

The model exits before completing. Try:

1. Clearer exit conditions in prompt
2. More explicit "keep going" instructions
3. Include the `<promise>COMPLETE</promise>` marker instruction

<Aside type="tip" title="Completion Marker">
ralph detects completion when the AI outputs `<promise>COMPLETE</promise>`. Always include this in your prompt's completion instructions.
</Aside>
