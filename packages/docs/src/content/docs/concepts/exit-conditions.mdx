# Exit Conditions

Exit conditions tell ralph when the job is done. Without them, ralph would loop forever. With good exit conditions, ralph knows exactly when to stop.

## The Exit Check

After each iteration, ralph asks: "Is the task complete?"

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  AI exits   │ ──▶ │ Check exit   │ ──▶ │   Done?     │
│  iteration  │     │  conditions  │     │             │
└─────────────┘     └──────────────┘     └──────┬──────┘
                                                │
                           ┌────────────────────┼────────────────────┐
                           │                    │                    │
                           ▼                    ▼                    ▼
                    ┌──────────┐         ┌──────────┐         ┌──────────┐
                    │   Yes    │         │    No    │         │  Max     │
                    │  ─────   │         │  ─────   │         │ reached  │
                    │  Exit    │         │  Loop    │         │  ─────   │
                    │  ralph   │         │  again   │         │  Exit    │
                    └──────────┘         └──────────┘         └──────────┘
```

## Types of Exit Conditions

### 1. Command-Based

Run a command and check the result:

```json
{
  "exitConditions": {
    "command": "npm test",
    "successExitCode": 0
  }
}
```

If `npm test` returns exit code 0, the task is complete.

You can also match output patterns:

```json
{
  "exitConditions": {
    "command": "npm test",
    "successPattern": "All tests passed",
    "failPattern": "failed"
  }
}
```

### 2. File-Based

Check for the existence of a marker file:

```json
{
  "exitConditions": {
    "markerFile": "DONE"
  }
}
```

Or check file contents:

```json
{
  "exitConditions": {
    "file": "PROGRESS.md",
    "contains": "Status: Complete"
  }
}
```

### 3. Iteration Limits

Always set a maximum to prevent runaway loops:

```json
{
  "exitConditions": {
    "maxIterations": 50
  }
}
```

<Aside type="caution" title="Always Set a Maximum">
Even if you have other exit conditions, always set `maxIterations`. It's your safety net against infinite loops and runaway API costs.
</Aside>

### 4. Time Limits

Limit total execution time:

```json
{
  "exitConditions": {
    "maxDuration": "2h",
    "maxDurationPerIteration": "10m"
  }
}
```

### 5. Cost Limits

Stop when spending reaches a threshold:

```json
{
  "exitConditions": {
    "maxCost": 50.00
  }
}
```

<Aside type="note">
Cost tracking requires the AI tool to report usage. Works with Claude Code and other tools that expose this data.
</Aside>

## Combining Conditions

Exit conditions can be combined with AND/OR logic:

<Tabs>
  <TabItem label="All Must Pass (AND)">
    ```json
    {
      "exitConditions": {
        "all": [
          { "command": "npm test", "successExitCode": 0 },
          { "command": "npm run lint", "successExitCode": 0 },
          { "command": "npm run typecheck", "successExitCode": 0 }
        ],
        "maxIterations": 30
      }
    }
    ```
  </TabItem>
  <TabItem label="Any Can Pass (OR)">
    ```json
    {
      "exitConditions": {
        "any": [
          { "markerFile": "DONE" },
          { "file": "PROGRESS.md", "contains": "All complete" }
        ],
        "maxIterations": 30
      }
    }
    ```
  </TabItem>
</Tabs>

## Designing Good Exit Conditions

### Be Specific

Bad:
```json
{ "command": "npm test" }
```

Good:
```json
{
  "command": "npm test -- --coverage",
  "successPattern": "Coverage: [89]\\d|100",
  "successExitCode": 0
}
```

The good version checks both that tests pass AND that coverage is at least 80%.

### Make Them Measurable

Bad:
```
Exit when the code is "good enough"
```

Good:
```json
{
  "command": "npm run lint && npm test && npm run typecheck",
  "successExitCode": 0
}
```

Measurable conditions are objective. ralph can check them automatically.

### Match Your Prompt

Your exit conditions should match what you asked the AI to do:

| Prompt | Exit Condition |
|--------|---------------|
| "Add tests until coverage is 80%" | Coverage command shows ≥80% |
| "Fix all TypeScript errors" | `tsc` returns exit code 0 |
| "Document all public functions" | No undocumented exports found |
| "Migrate from X to Y" | No imports from X remain |

### Include Safety Limits

Always have fallbacks:

```json
{
  "exitConditions": {
    "primary": {
      "command": "npm test",
      "successExitCode": 0
    },
    "limits": {
      "maxIterations": 50,
      "maxDuration": "4h",
      "maxCost": 100.00
    }
  }
}
```

## Exit Condition Patterns

### Pattern: Test-Driven

```json
{
  "exitConditions": {
    "command": "npm test",
    "successExitCode": 0,
    "maxIterations": 30
  }
}
```

Loop until all tests pass.

### Pattern: Coverage Target

```json
{
  "exitConditions": {
    "command": "npm test -- --coverage --coverageReporters=text",
    "successPattern": "All files.*\\|\\s*(8\\d|9\\d|100)\\s*\\|",
    "maxIterations": 50
  }
}
```

Loop until coverage hits 80%+.

### Pattern: Zero Errors

```json
{
  "exitConditions": {
    "command": "npm run lint",
    "successPattern": "0 errors",
    "maxIterations": 20
  }
}
```

Loop until linting shows no errors.

### Pattern: Marker File

Tell the AI in your prompt:
```markdown
When all work is complete, create an empty file called `DONE`.
```

Config:
```json
{
  "exitConditions": {
    "markerFile": "DONE",
    "maxIterations": 100
  }
}
```

This gives the AI explicit control over when to signal completion.

### Pattern: Progress File

Tell the AI to update progress:
```markdown
Update PROGRESS.md after each major milestone.
When done, change status to "Complete".
```

Config:
```json
{
  "exitConditions": {
    "file": "PROGRESS.md",
    "contains": "Status: Complete",
    "maxIterations": 100
  }
}
```

### Pattern: Git-Based

Check for specific commits or no changes:

```json
{
  "exitConditions": {
    "command": "git status --porcelain",
    "successPattern": "^$",
    "maxIterations": 20
  }
}
```

Exit when there are no uncommitted changes (AI has committed everything).

## Debugging Exit Conditions

If ralph isn't exiting when expected:

1. **Check the command manually**
   ```bash
   npm test
   echo $?  # Should be 0 for success
   ```

2. **Check pattern matching**
   ```bash
   npm test 2>&1 | grep -E "your-pattern"
   ```

3. **Use verbose mode**
   ```bash
   ralph run --verbose
   ```
   This shows exactly what conditions are checked and why they passed/failed.

4. **Test conditions in isolation**
   ```bash
   ralph check-exit  # Runs exit conditions without starting a loop
   ```
