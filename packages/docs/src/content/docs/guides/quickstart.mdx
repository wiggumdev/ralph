# Quick Start

Let's run your first ralph loop. We'll add tests to a simple project—the kind of tedious, repetitive work that ralph excels at.

<Aside type="tip">
This guide assumes you've [installed ralph](/guides/installation/) and have an AI tool like Claude Code available.
</Aside>

## The 5-Minute Version

<Steps>

1. **Initialize ralph**

   ```bash
   cd your-project
   ralph init
   ```

   Select your adapter (claude recommended) when prompted.

2. **Edit your prompt**

   Open `.plans/PROMPT.md` and add your task:

   ```markdown
   # Task: Fix All TypeScript Errors

   Fix all TypeScript errors in this project.

   ## Process
   1. Run `npx tsc --noEmit` to see errors
   2. Fix one error at a time
   3. Re-run to verify fix

   ## Completion
   When `npx tsc --noEmit` exits with code 0, output:
   <promise>COMPLETE</promise>
   ```

3. **Run the loop**

   ```bash
   ralph run
   ```

</Steps>

That's it. ralph will:
1. Start your AI tool with the prompt
2. Let it work until it exits
3. Reset context and feed the same prompt
4. Repeat until the AI outputs `<promise>COMPLETE</promise>` or max iterations

## A Proper Example

Let's do something more structured. We'll add tests to a Node.js project.

<Steps>

1. **Set up the example**

   ```bash
   cd my-project
   npm install
   ```

2. **Initialize ralph**

   ```bash
   ralph init
   ```

   This creates:
   - `.ralph/config.toml` — Configuration
   - `.plans/prd.json` — Feature definitions
   - `.plans/PROMPT.md` — Your task prompt
   - `.plans/progress.txt` — Progress tracking

3. **Configure ralph**

   Edit `.ralph/config.toml`:

   ```toml
   adapter = "claude"
   maxIterations = 20
   ```

4. **Create your task prompt**

   Edit `.plans/PROMPT.md`:

   ```markdown
   # Task: Add Comprehensive Tests

   Add unit tests for all modules in `src/`.

   ## Guidelines
   - Use Jest (already configured)
   - Each module should have a corresponding `.test.js` file
   - Aim for >80% coverage
   - Test both success and error paths

   ## How to Check Progress
   1. Run `npm test` to see current status
   2. Check progress.txt for what's done

   ## Update Progress
   After completing each module, add it to progress.txt

   ## Completion
   When `npm test -- --coverage` shows >80% coverage and all tests pass, output:
   <promise>COMPLETE</promise>
   ```

5. **Run the loop**

   ```bash
   ralph run
   ```

6. **Watch it work**

   Each iteration:
   - The AI reads the prompt and current codebase
   - Makes progress (adds tests, fixes issues)
   - Updates progress.txt
   - ralph checks if the AI signaled completion
   - If not done, loops again with fresh context

</Steps>

## Understanding the Output

ralph displays:
- Current iteration number
- Token usage per iteration
- Exit reason when complete

The run ends when:
- AI outputs `<promise>COMPLETE</promise>` (success)
- Max iterations reached
- User interrupts (Ctrl+C)
- Error occurs

## Common Patterns

### Pattern 1: Fix All Errors

```markdown
# Task: Fix Linting Errors

Fix all ESLint errors.

## Process
Run `npm run lint` to see errors. Fix them one at a time.

## Completion
When `npm run lint` exits with code 0, output:
<promise>COMPLETE</promise>
```

### Pattern 2: Migration

```markdown
# Task: Migrate API Calls

Migrate all usages of `oldApi` to `newApi`.

## Find work
`grep -r "oldApi" src/`

## Migration rules
- `oldApi.fetch()` → `newApi.get()`
- `oldApi.send()` → `newApi.post()`

## Completion
When grep returns no results, output:
<promise>COMPLETE</promise>
```

### Pattern 3: Documentation

```markdown
# Task: Add JSDoc Comments

Add JSDoc comments to all exported functions in src/.

## Guidelines
- Include @param and @returns
- Keep descriptions concise

## Progress
Track completed files in progress.txt

## Completion
When all exports are documented, output:
<promise>COMPLETE</promise>
```

## Tips for Effective Prompts

<Aside type="caution" title="The Prompt Matters">
The same prompt runs every iteration. Make it clear, self-contained, and include instructions for checking progress.
</Aside>

**Good prompt structure:**

```markdown
# Task
[What needs to be done]

# Guidelines
[How to do it well]

# Checking Progress
[How to see what's already done]

# Completion
[When to output <promise>COMPLETE</promise>]
```

**Include these elements:**

1. **Context** — What's the project? What's the goal?
2. **Constraints** — Style guides, patterns to follow
3. **Progress markers** — How to check what's done
4. **Completion signal** — When to output the completion marker
