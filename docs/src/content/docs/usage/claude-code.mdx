# Using ralph with Claude Code

Claude Code is Anthropic's official CLI for Claude. It's the most popular tool for ralph loops, and ralph has first-class support for it.

## Setup

<Steps>

1. **Install Claude Code**

   ```bash
   npm install -g @anthropic-ai/claude-code
   ```

2. **Set your API key**

   ```bash
   export ANTHROPIC_API_KEY="sk-ant-..."
   ```

3. **Verify installation**

   ```bash
   claude --version
   ralph doctor
   ```

</Steps>

## Configuration

Basic configuration for Claude Code:

```json
{
  "tool": "claude",
  "toolOptions": {
    "model": "claude-sonnet-4-20250514",
    "dangerouslyAllowAllCommands": false
  }
}
```

### Model Selection

| Model | Best For | Cost |
|-------|----------|------|
| `claude-sonnet-4-20250514` | Balance of speed and capability | $$ |
| `claude-opus-4-20250514` | Complex reasoning tasks | $$$$ |

<Aside type="tip" title="Model Recommendation">
Start with Sonnet. It's fast, capable, and cost-effective for most tasks. Switch to Opus only for tasks requiring deep reasoning.
</Aside>

### Full Options

```json
{
  "tool": "claude",
  "toolOptions": {
    "model": "claude-sonnet-4-20250514",
    "dangerouslyAllowAllCommands": false,
    "allowedCommands": ["npm", "git", "node"],
    "maxTurns": 50,
    "timeout": 600000
  }
}
```

## Prompt Patterns

### Pattern 1: Task with Progress Tracking

```markdown
# Task: Add Unit Tests

Add comprehensive unit tests for all modules in `src/services/`.

## Context
- This is a TypeScript project using Jest
- Follow existing test patterns in `src/__tests__/`
- Each service should have its own test file

## Requirements
- At least 80% code coverage
- Test both success and error paths
- Mock external API calls

## Progress Tracking
1. Check PROGRESS.md for completed work
2. Update PROGRESS.md after each service is tested
3. Run `npm test` to verify

## Exit Condition
When `npm test -- --coverage` shows >80% coverage and all tests pass.
```

### Pattern 2: Refactoring with Verification

```markdown
# Task: Migrate to New API

Migrate all usages of `oldApi` to `newApi`.

## How to Find Work
```bash
grep -r "oldApi" src/
```

## Migration Rules
- `oldApi.fetch()` → `newApi.get()`
- `oldApi.send()` → `newApi.post()`
- Error handling stays the same

## Verification
Run `npm run typecheck` after each file change.

## Exit Condition
`grep -r "oldApi" src/` returns no results.
```

### Pattern 3: Bug Hunting

```markdown
# Task: Fix Failing Tests

Fix all failing tests in the test suite.

## Current Status
Run `npm test` to see failing tests.

## Guidelines
- Read the test to understand intent
- Check the implementation
- Fix the bug (prefer fixing implementation over tests)
- If test is wrong, explain why in commit message

## Process
1. Run tests to see failures
2. Fix one failing test at a time
3. Commit after each fix
4. Repeat until all pass

## Exit Condition
`npm test` exits with code 0.
```

## Claude Code Hooks

Claude Code supports hooks that can integrate with ralph:

### Stop Hook (The Original Ralph)

The classic ralph pattern uses Claude Code's stop hook:

```json
// .claude/hooks.json
{
  "stop": {
    "command": "check-if-done.sh",
    "blocking": true
  }
}
```

When Claude tries to exit, the hook runs. If it returns non-zero, Claude continues with the same prompt.

<Aside type="note" title="ralph vs Hooks">
ralph provides a higher-level interface than raw hooks, with better logging, state management, and configuration. Use ralph unless you need very custom behavior.
</Aside>

### Integrating Hooks with ralph

ralph can work alongside Claude Code hooks:

```json
{
  "tool": "claude",
  "toolOptions": {
    "preserveHooks": true
  }
}
```

## Cost Management

Claude API usage can add up. ralph provides several cost controls:

### Set Spending Limits

```json
{
  "exitConditions": {
    "maxCost": 50.00
  }
}
```

### Monitor Usage

```bash
ralph run --verbose
```

Shows token usage and cost per iteration.

### Cost Estimation

```bash
ralph run --dry-run
```

Estimates cost based on prompt size and iteration limits.

## Performance Tips

### 1. Keep Prompts Focused

Large prompts consume tokens every iteration. Keep them concise:

```markdown
# Good: Focused prompt
Add tests for untested functions. Check PROGRESS.md for status.

# Bad: Overly detailed prompt
[500 lines of instructions repeated every iteration]
```

### 2. Use File References

Instead of embedding content in prompts:

```markdown
# Good
See CODE_STANDARDS.md for coding guidelines.

# Bad
[entire coding standards document embedded in prompt]
```

### 3. Efficient Exit Conditions

Fast exit conditions reduce overhead:

```json
{
  "exitConditions": {
    // Fast: file existence check
    "markerFile": "DONE",

    // Slower but more reliable: run tests
    "command": "npm test"
  }
}
```

### 4. Model Selection by Task

| Task Type | Recommended Model |
|-----------|-------------------|
| Mechanical refactoring | Sonnet |
| Test writing | Sonnet |
| Complex bug fixing | Opus |
| Architecture decisions | Opus |
| Documentation | Sonnet |

## Troubleshooting

### "Rate limited"

You've hit API rate limits. Options:

```json
{
  "toolOptions": {
    "retryOnRateLimit": true,
    "rateLimitBackoff": "exponential"
  }
}
```

Or reduce parallelism in your prompts.

### "Context too long"

Your codebase is too large for a single read. Strategies:

1. Focus the prompt on specific directories
2. Use `.claudeignore` to exclude files
3. Let the model navigate incrementally

### "Model keeps repeating"

The model isn't seeing state changes. Ensure:

1. Your prompt references state files
2. State files are being updated
3. Git changes are being committed

### "Unexpected exits"

The model exits before completing. Try:

1. Clearer exit conditions in prompt
2. More explicit "keep going" instructions
3. Check Claude Code logs for errors

## Example: Full Test Coverage Run

A complete example of using ralph with Claude Code:

**ralph.config.json:**
```json
{
  "tool": "claude",
  "toolOptions": {
    "model": "claude-sonnet-4-20250514"
  },
  "prompt": {
    "file": "TASK.md"
  },
  "exitConditions": {
    "command": "npm test -- --coverage",
    "successPattern": "All files.*\\|\\s*(8\\d|9\\d|100)",
    "maxIterations": 30,
    "maxCost": 25.00
  },
  "state": {
    "progressFile": "PROGRESS.md",
    "autoCommit": true
  }
}
```

**TASK.md:**
```markdown
# Add Test Coverage

Goal: Achieve 80%+ test coverage for src/services/.

## Current Status
Run `npm test -- --coverage` to see current coverage.
Check PROGRESS.md for completed services.

## Guidelines
- One test file per service
- Test success paths, error paths, edge cases
- Mock external dependencies
- Follow patterns in existing tests

## After Each Service
1. Run tests to verify
2. Update PROGRESS.md
3. Commit with message: "test(services): add tests for [name]"

## Done When
Coverage is 80%+ for all files in src/services/.
```

**Run:**
```bash
ralph run
```
